    使用说明 / 常见问题
    • 完全本地运行：页面不发起任何网络请求，文件内容不会离开你的电脑。
    • 支持的算法：MD5、SHA-1、SHA-224、SHA-256、SHA-384、SHA-512、SHA3-256、BLAKE2b-512、CRC32。可多选，同一遍文件读取中一次算完。
    • 清单格式：GNU 的 哈希␣␣文件名、二进制标记 哈希 *文件名、BSD/OpenSSL 的 SHA256 (文件名) = 哈希值、certutil 的「XXX hash of file …」输出都支持；# 开头的行视为注释。
    • 算法识别：清单里写了算法名（BSD/certutil 格式）就按名称匹配；只写哈希值时按长度识别——8 位=CRC32，32 位=MD5，40 位=SHA-1，56 位=SHA-224，64 位=SHA-256 或 SHA3-256，96 位=SHA-384，128 位=SHA-512 或 BLAKE2b-512。同长度的两种算法无法区分时会按长度匹配（任意一种对上即通过）。
    • 匹配规则：先按“相对路径”比对，再按“文件名”比对（Windows 下不区分大小写）；哈希值大小写不敏感。
    • 只粘贴了一个哈希值？会被当作通用期望值，与加入的文件逐一比对，方便做单文件校验。
    • 性能：SHA-1/256/384/512 在 ≤512 MB 时走浏览器原生 crypto（最快）；MD5、SHA3、BLAKE2b、CRC32 没有原生实现，用内置纯 JS 引擎；更大或强制流式时所有算法都用 JS 分块计算。SHA-512/BLAKE2b/SHA3 的 JS 实现较慢（纯 JS 大整数运算），GB 级文件请留出时间。
    • 提示：校验通过只能说明文件与清单一致；请确认校验清单本身来自官方可信渠道（HTTPS 官网、签名邮件等）。MD5/SHA-1 已不具备抗碰撞能力，仅用于校验下载完整性，不应用于安全场景。
